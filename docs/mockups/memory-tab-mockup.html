3 Athlete Context

The document Joe reads, changed by asking Joe

Visually a text block like the Program tab: one readable document assembled from the context the AI already uses today — profile columns, the goal, injury history, memory facts with their pins and expiries, watch notes, and the old dated notes. Nothing invented for display; this IS his briefing.

To change it, the athlete types in the box at the bottom. Joe applies the change with his existing memory tools — add a fact, edit one, clear one — and answers in one line right above the box. The highlighted line just landed from the request shown.

Per your ruling the box can update just about anything in athlete memory — it is the explicit fail-safe: when the AI misses a preference or an important detail in conversation, the athlete fixes the context directly here instead of staying frustrated. Weight, schedule, equipment, injuries, goals, preferences: all fair game.

Profile numbers render from their real columns, so this tab never drifts from Settings. Watch notes stay visible per your ruling: you can trace any behavior to the exact input behind it.

4 Out of scope

Joe holds the line

Anything that would change the AI's personality, rules, or scope gets denied: the box turns red and a flag message pops. Joe stays a coach; the athlete's context stays facts about the athlete.

Three layers deep, per your ruling: Joe's own judgment is the front gate (he reads the request before touching anything), the deterministic injection validator screens every fact he tries to write, and the server gateway enum-pins the table's columns. A request has to beat all three — the UI is the shallowest layer, not the only one.

The age guard (13+ platform): age and birthday are the one profile carve-out — Joe never changes them from this box, because age drives real protections (the under-16 rules, minor-safety behavior). "I'm actually 17" gets a polite decline pointing to support, so an account can never talk itself out of its protections here.

The deny is polite and specific, then the box clears for the next ask. Nothing is written, nothing is logged into his memory from a flagged request. Denial red is a hard stoplight red, reserved for exactly this.

THE SIZE CEILING — remember a lot, inject a bounded window

The trick that keeps this cheap: the athlete's memory STORE can hold plenty, but what gets injected into each message is a windowed slice with a hard ceiling, so per-message cost never scales with how much an athlete hoards.

The caps (all already server-enforced): 240 characters per fact · 60 active facts stored · 24 facts injected per message (pinned first, then newest). Worst case that is roughly 1,500 tokens of memory per message — about half a cent uncached, a twentieth of a cent on a prompt-cache hit at Sonnet pricing. A heavy athlete sending 300 messages a month lands between pennies and ~$1.50 in the absolute worst case, against $14.99/mo today and comfortable even at a $5 price. For scale: the entire 30-day AI bill across every athlete is ~$24.

When the store hits 60, Joe consolidates instead of growing: merges near-duplicates, drops expired and stale unpinned facts, and tells the athlete if something has to give. Memory stays curated, not infinite — and the athlete never sees an error, just a coach keeping tidy notes. The Older-notes blob is already capped and shrinks to zero when it migrates.
